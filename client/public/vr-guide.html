Return to VYUHA

One exercise. Two workstations.

The ordinary browser is the primary supported training experience. The optional VR observation cockpit is an experimental forward-port using the same worker, accepted actions, scoring, recovery and Ghost AAR.

Desktop preview

  1. Prepare the exercise in Training Ground.
  2. Choose Open VR observation cockpit. Without WebXR, use the visible desktop controls or click the spatial console.
  3. Start, select a currently reported contact, designate, review observed evidence and explicitly choose type/identity.
  4. Confirm classification. Review the same range, resource and restricted-zone warnings as the browser. Warned attempts remain recordable for training review; the engine decides their result. Select a response, then explicitly confirm it within eight seconds. A changed warning cancels confirmation; reconsider and arm again.
  5. Closing the cockpit pauses an active exercise. Return to the browser; a server-controlled pause requires the officer to resume.
  6. End the exercise through the ordinary workspace. Accepted actions and server verification appear in the existing Ghost review.

Immersive WebXR

Requires a compatible browser/headset, tracked controller target rays and a browser-trusted secure origin. Enter VR is capability-gated. This is seated observation: no locomotion, forced contact-follow camera, teleportation or hand-only interaction. Point either controller and release its trigger. No supported rays means no supported immersive input; use the headset system exit and desktop controls.

Visibility loss, system exit or graphics failure pauses the drill and clears response confirmation. Returning visibility never automatically resumes. Exit and reopen after a graphics-context failure.

Trusted LAN deployment

Run the current normal setup/build first. Use scripts/make-cert.py according to the HTTPS operator guide. The certificate must cover the exact reachable LAN IP/hostname and be trusted by the headset browser. Never bypass certificate warnings or distribute the private key. Set VYUHA_SSL_CERTFILE and VYUHA_SSL_KEYFILE, then run bash scripts/start-vr.sh. This wrapper delegates current Unit Mode preflight/startup; it installs no trust and makes no network downloads.

Evidence limits

Source-current software validation is recorded in docs/vr-unification/FINAL-INTEGRATION-REPORT.md in the repository. Historical IWER results do not certify this source. Physical headset performance, comfort, controller ergonomics, LAN HTTPS and device acceptance remain pending. Desktop preview and WebXR emulation are software tests, not physical headset footage. All sensors, signatures and response resources remain illustrative training models.

VR displays current reported geometry and sensor observations, never post-exercise reference truth. It does not improve detection, reveal hidden identity or guarantee response success. Browser administration, Instructor, Crew and analytics remain ordinary pages.
