# Technical selection and provenance

This implements the already researched semantic-world/episode-compiler direction in `docs/next-generation/flagship-transformation/research/product-direction.md`; it does not repeat competitive research. Source inspection found one hardcoded facility per terrain and unrelated raid boxes, so a frozen public site was selected over another material tweak. Its measured difference is actual spatial composition plus changed modeled evidence opportunities, not presumed learning efficacy.

The installed Three.js r180 geometry merger requires compatible attributes and returns null on incompatible batches; the implementation keeps the existing position/normal/UV/color kit contract and merges static pieces by material. Primary reference: [Three r180 BufferGeometryUtils](https://raw.githubusercontent.com/mrdoob/three.js/r180/examples/jsm/utils/BufferGeometryUtils.js). The [official r180 optimization manual](https://raw.githubusercontent.com/mrdoob/three.js/r180/manual/en/optimize-lots-of-objects.html) explains mesh/draw-request overhead and geometry merging. Applying that principle to bounded metric buildings is an engineering inference, not a guarantee of faster frames. Actual budgets and browser measurements are recorded separately.

All new architecture/site definitions are original synthetic geometry and public metric layouts. Existing locally bundled licensed assets/materials are reused; no competitor code, proprietary scenery or new remote asset was copied. The site is not surveyed geography or an operational model. Explicit Defer, geometric LOS, observed availability and human reasoning remain distinct concepts.
