# VYUHA: one next-generation product, three connected flagships

26 October 2026. Research/design workstream, read-only source baseline `0664dc4` on `feature/vyuha-next-generation`. No repository/runtime/dependency/viewport change, physical test or product benchmark was performed by this workstream. This is a target and implementation decision, not an assertion that the flagships are delivered.

## The correction

The product is the exercise world and the decisions a learner can make within it. Its core unit is an **instructional episode**, not a route, chart, quiz or optional tool. Its common interaction unit is an **evidence moment**: the exercise/session, reported subject, logical time/order, observation boundary, source and allowed perspective. Briefing, live observation, decision, review, practice selection, instructor intervention and authoring must operate on those units.

The target journey is: understand a consequential task in a synthetic place → investigate available reports → make an explicit decision or preserve justified uncertainty → see the accepted response and simulated consequence → reconstruct the information available then → practise a semantically different case → demonstrate the skill independently. An instructor can author/rehearse, conduct, review and compare that same episode. This is a product hypothesis; success must be demonstrated and learning effects require participants.

The first visible delivery should replace the ordinary Training Ground composition with a persistent simulation stage and deliberate **Observe ↔ Decide** instrument states. This is only one connected foundation for Flagship A, not a claim that all of A/B/C is done.

## One architecture, not three feature piles

1. **Episode specification**: immutable ID/version, task objective, scenario/world/sensor policy references, learner role, planned evidence opportunities, allowed guidance, meaningful alternative paths, misconception/feedback obligations, intervention schedule and comparison/variation conditions. Existing v1 catalog contexts remain exact snapshots. A new semantic contract is opt-in, not a silent mutation of previous score meanings.
2. **Evidence frame**: session/scenario/engine/policy identity, tick and event order, reported subject/pose/age, channel availability and allowed perspective. Training, Crew, Fusion, Theatre and instructor selected-view adapters consume the same model. Runtime observations must never be obtained from the reference-world adapter.
3. **Presentation controller**: phase + instrument mode + selected reported subject + foreground channel + modal/focus state. It neither owns the worker clock nor generates accepted actions. UI Back/Observe/Decide is routed separately from classify/designate/respond. Passive telemetry cannot change the active instrument or steal focus.
4. **Authoritative runtime and append-only evidence**: retain the existing deterministic simulation/server verification path until a new version is explicitly admitted. Acquisition/dwell/release, instructions, actions and interventions need distinct typed events; no camera crop or optional note is relabeled as acquisition.
5. **World/episode compiler**: a semantic scene specification compiles consistent visual representations, authoritative volumes, temporal scenario events and instructional opportunity tests. This is the shared foundation for real visual authoring, scenario diversity, review and later higher-fidelity renderers.
6. **Render adapters and resource budgets**: one scene/context for the primary task, versioned scene presentation inputs, quality assets/LODs and explicit warm-up/disposal. DOM, XR and instructor overview are compositions of shared meanings. A WebGPU/TSL or native renderer replacement must prove a material advantage on this actual workload rather than being a requirement for the UX rewrite.
7. **Instructional policy/evaluation**: target genuine evidence gaps and semantic variation, retain independent assessment pools, expose uncertainty and abstention, test the policy's own decisions. Predictive fit and human transfer/retention are separate validation programs. Do not present a synthetic trace or illustrative BKT posterior as calibrated proficiency.

A shared persistent presentation context does not mean leaving hidden cameras, caches or selection active across exercise identities. Reset scoped presentation state on session changes; preserve it across deliberate Observe/Decide transitions within one session. A fallback/remount remains appropriate after genuine context loss.

## Alternatives and engineering decision

| Alternative | Strength | Problem / decision |
|---|---|---|
| Keep existing permanent form column and improve spacing/materials | Low migration risk | Does not change the observation→reasoning task or recover scene attention. Insufficient as the primary flagship delivery. |
| Fully diegetic/in-world controls for all functions | Strong visual novelty | Occlusion, readability, input accessibility and XR comfort risks. Use semantic DOM for desktop and purpose-built spatial instruments in XR; do not require precise mesh controls. |
| Immediately replace Three/WebGL2 with WebGPU/Unreal | Potential graphics ceiling/authoring tools | Current custom thermal/shader/inspection/XR paths and M1/offline delivery create real migration cost. Retain as a measured renderer spike behind the presentation/world contracts; not a prerequisite for a conspicuous product improvement. |
| Persistent world plus task-driven instrument states and semantic episode/world compiler | Substantially changes entering/observing/deciding/authoring/reviewing while retaining authority | Chosen direction. Deliver connected slices; do not call the entire flagship complete after the initial composition. |

## First connected delivery and visual identity

**Current → superior approach → target → architecture → implementation → proof**:

- Current: large marketing-style arrival followed by a fixed-form simulator. Research precedent: task-focused viewport, explicit input layers and selection-linked properties. Target: entering and operating a coherent observation station. Architecture: existing authoritative App + a pure instrument/focus state controller + one persistent renderer and reused decision/evidence components. Implementation: concise interactive mission composition; Observe/Decide modes; selected-report capsule; deliberate evidence/action instrument; same mission identity into completion/Theatre. Proof: real task completion, baseline/candidate screenshots and measurements below.
- In parallel, simulation work settles versioned episode/world/acquisition contracts and implements a genuine new task/authoring slice behind explicit admissions. Training intelligence work specifies feedback opportunities, meaningful variants and instructor interventions against those same episode/evidence IDs. A scheduler alone is a dependency, not Flagship B completion.

Reuse VYUHA's established premium brand and licensed fonts, but change hierarchy. The world uses authored warm/neutral industrial material colors and believable natural light; instruments use restrained cool-neutral surfaces, one selected-evidence accent and reserved warning/fault colors. The observation surface is quiet; a decision surface is opaque and readable; review distinguishes available evidence from authorized reference; authoring exposes geometry/time diagnostics intentionally. Text + shape + labels reinforce state. Do not add bloom, HUD texture, gratuitous scan lines, transparent nested cards or tiny monospaced labels to make it “military.”

The serif entry headline in the existing capture behaves like a landing page. Replace its job with the actual task/objective, environment and preparation/readiness affordances. Live instructions and decisions need readable sans-serif hierarchy; time/order/IDs can use mono where it helps scanning. Preserve secondary workspace discovery without making global route navigation dominate active training.

| Concern | First-slice measurement and gate |

| Decision usability | At1152×648 and1280×720, selected subject, key cue/uncertainty, explicit action and pending/accepted feedback must remain one context. The primary action cannot require searching/scrolling the document or move under a pointer because telemetry/feedback changes. | Readability | Essential instructions/body14–16px, opaque/strongly backed controls, normal-text contrast≥4.5:1, named controls, visible focus, no color-only state. Do not solve fitting by shrinking decision type/identity labels to8–11px. |
| Mobile/tablet | At390×844 and768×1024, explicit Sensor/Radar/Decision modes, persistent selected-report/status summary, named Back to observation, ≥44px targets, no horizontal document overflow, no gesture-only drawer. Sensor loss/resize cannot drop selection or hide the route back. |
| Keyboard/focus | Follow a fixed reported-contact→evidence→explicit classify→response→Observe→completed review task. Record tab/context switches and required document scrolls against baseline. No view change dispatches an action. Modals/sheets own Escape/Back, return focus predictably, and never let passive updates move focus. |
| One authoritative task | The same accepted payloads, ordered receipts, confidence/Fusion attribution, offline queued actions and server-verified record result must persist. Unknown/stale reports remain visibly unknown/stale. No free reference camera during live sensor operation. |
| Renderer continuity | Observe/Decide/channel/panel transitions do not create a second renderer or restart worker/replay. Instrument selection remains scoped to session identity; context-loss fallback and recovery stay explicit. Count scene/canvas mounts with development instrumentation. |
| Fair performance comparison | Compare a fixed-canvas workload first to isolate graphics changes, then the natural full-viewport workload to measure actual product cost. A larger stage renders more pixels and changes tiny-contact pixel footprint; do not claim a speedup from lowering DPR or quietly changing quality. Record frame p95/p99, interaction latency, first/repeat load and heap/resource behavior across repeated entry/exit. |
| Review continuity | Completion retains attempt identity, observed/scoring horizons and pending-verification status. The Theatre opens an actual original moment, distinguishes reference from available evidence and leads to a real new practice attempt. No fresh canonical score is substituted for the original. |
| Accessibility/XR | Focused automated semantics + actual keyboard/pointer layouts support desktop claims. Screen-reader, physical headset readability/comfort/FPS, trusted separate-device HTTPS and native-platform deployment remain distinct gates unless actually tested. |

No usability-time percentage or learning gain should be claimed until the matched task is measured. The proposed thresholds are product decisions for this first slice, not numbers borrowed from a vendor screenshot.
