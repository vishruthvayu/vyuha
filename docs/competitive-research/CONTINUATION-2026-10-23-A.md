## New primary-source discoveries

### A1. Numbas: generation contracts, bounded rejection and assessment authoring

The [question reference](https://docs.numbas.org.uk/en/latest/question/reference.html) documents variables shared by statement, answers and advice, deterministic seeded generation, validity conditions and a maximum generation-attempt limit. Preview locks do not freeze delivered variants. These are DOCUMENTED authoring/runtime behaviors, not independently executed here. The useful addition is a **content-authoring preview receipt**: frozen variable assignments and validity failures must accompany a generated assessment; “works in preview” is not adequate evidence for the delivered generator.

Numbas’s [adaptive-marking design notes](https://www.numbas.org.uk/behind-the-design/adaptive-marking.html) explain dependency invalidation when an upstream answer changes and warn that some substituted answers make downstream parts trivially easy. This is an explicitly rough design document, not evaluation evidence. For VYUHA, it motivates checking **answer-conditioned downstream difficulty and cue leakage**, while retaining separate errors rather than importing its mathematics marking rule into existing scores.

The [diagnostic-mode documentation](https://docs.numbas.org.uk/en/latest/exam/diagnostic.html) describes knowledge graphs, scripted selectors and a DIAGNOSYS algorithm that propagates passes to prerequisites/fails to dependent topics. It also retains an explicit November 2022 “not used on real students yet” note. Consequently, neither the current document nor a knowledge graph establishes valid prerequisite inference. **Do not copy propagation into Director mastery**: a passed advanced task must not silently mint observations for untested competencies. This is a concrete negative design lesson for R03/R07.

[License documentation](https://docs.numbas.org.uk/en/latest/licensing.html) says runtime/editor code is Apache-2.0, content belongs to authors, and identifies separately licensed dependencies including LGPL TinyMCE in the editor. The [runtime root license](https://github.com/numbas/Numbas/blob/master/LICENSE) was inspected. A headline open-source license does not clear question content or the entire editor bundle. Reference patterns only; no Numbas dependency is needed.

### A2. XState graph utilities: authoring reachability is a separate deliverable from tutoring

The maintainer’s [Graph & Paths documentation](https://stately.ai/docs/graph) shows directed-state graph traversal, shortest paths and non-cyclic simple paths. It currently identifies itself as **XState v6 alpha** and moves utilities into `xstate/graph`; existing package advice may be version-specific. This is DOCUMENTED API behavior, not a version recommendation or runtime reproduction. The inspected [root license](https://github.com/statelyai/xstate/blob/main/LICENSE) is MIT; Studio/service terms are separate.

The additive idea for R41 is a **bounded, author-visible path audit** before a lesson becomes selectable. An authored route can have legal alternatives, error/remediation states and an explicit finish without forcing one button sequence. Generate one short witness for each reachable state and inspect non-cyclic alternatives. Do not claim full interaction coverage from shortest paths alone, and do not claim exhaustive exploration where context values, timers or cycles are unbounded. Keep a small finite abstraction and list its exclusions. An independent validator can implement this without adding XState to the runtime.

### A3. Inspect AI: distinguish tutor failures from evaluation failures

The UK AI Security Institute’s [scoring policy](https://inspect.aisi.org.uk/scoring-policy.html) distinguishes a model verdict, a scoring error and an unscored sample; errors/unscored outcomes affect denominators differently. It explicitly treats a grading model as a measurement instrument. This is DOCUMENTED evaluation-framework behavior; no pedagogical efficacy follows. The new actionable issue for R42 is **denominator integrity**: a broken evidence lookup or malformed grader result must not be counted as tutor abstention, correctness or successful grounding.

[Custom scorer documentation](https://inspect.aisi.org.uk/custom-scorers.html) exposes separate value, reason, explanation and metadata fields. Its [log documentation](https://inspect.aisi.org.uk/eval-logs.html) describes evaluation logs, score editing/history and APIs. These patterns support separate immutable baseline output and derived rubric versions; they are not permission to edit original learning evidence. The inspected [root license](https://github.com/UKGovernmentBEIS/inspect_ai/blob/main/LICENSE) is MIT. Reference first: a small deterministic local harness needs neither Inspect, model downloads nor an online grader.
