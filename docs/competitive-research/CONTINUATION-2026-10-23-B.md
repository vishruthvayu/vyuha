# Research B — evidence-centered UI, 3D and XR

Research snapshot: 23 October 2026. Checkout `feature/vyuha-next-generation`, HEAD `fc1b30ebd018e9e434c897ea036ecab3392632fa`; working files may include concurrent implementation. Read the existing ROADMAP, EXPANSION, BASELINE, capability index and selected current source. This extends their findings; it does not repeat R01 startup research or claim a release, headset acceptance or learning benefit.

## One coherent direction

Make VYUHA a **time-aware evidence cockpit**: the same selected contact, observation timestamp, sensor state and decision status should remain understandable across radar, optical view, evidence dock, Ghost and XR. Richer 3D should explain what was observable and why. Controls should share semantic definitions and accepted action dispatch, while each presentation suits its medium. Visual polish supports this; it cannot substitute for trustworthy state transitions.

Current source already provides substantial foundations. `Scene.tsx` applies `ObservationVisibility` before camera framing, gates close-up recognition and distinguishes reference-truth review. `VRWorld.tsx` uses observed contacts and native per-eye depth, deliberately excludes browser follow-camera/inspection passes and shares the environment. `world/kit.ts` batches original metric geometry by material; Environment supports authoritative boxes, thermal material swaps, static occlusion and translucent AAR dressing. `DecisionWorkspace.tsx` already separates decisions from selected evidence. `VRCockpit.tsx` has explicit action choices, receipt locking and expiring response confirmation. Proposing those features as absent would be incorrect.

The remaining architectural seam is **coherent presentation state**: Ghost explicitly keeps decision evidence pinned while its replay cursor moves, browser and XR instruments are implemented separately, and XR surfaces use fixed positions/text rasterization. The next work should make time, stale evidence and instrument behavior explicit before adding free camera motion, complex postprocessing or decorative panels.

## Three measurable implementation experiments

**1. Time/selection contract pilot — R11, with R10/R12.** Add a small presentation model keyed by immutable session ID, selected contact/event, playhead tick, evidence tick and pin state. Pilot only Ghost's existing timeline, evidence inspector and one scene. Keep original observations and scores untouched. Explicitly label “decision evidence at tick X / replay at tick Y”; expose link/unlink and step-to-event by keyboard/simple pointer. Acceptance: delayed/out-of-order data, seek across gaps, pin then play, session switch and restore show zero future-evidence leaks or stale session selections. Compare a fixed five-question evidence-location task before/after: completion time, wrong-time answers, unnecessary panel changes and keyboard steps. Targets require a baseline; no learning claim.

**2. Spatial explanation lens — R19/R35/R47, authoring R14.** In authorized AAR/author preview only, provide a toggleable diagnostic layer for sensor origin, authoritative obstruction boxes and the selected time-valid observation position. Use linked selection with a plain text explanation and optional cutaway/helpers inspired by the demo. Keep decorative scenery visibly distinct from authoritative blockers; never expose truth geometry/contact poses during assessed live operation. Acceptance: fixtures with an occluder, no optical observation, late/coasted radar cue and mismatched decorative prop. Expected rendered explanation must agree with canonical observation/occlusion rules; switching the lens must change no accepted actions or review payloads. Measure explanation correctness, false inferred visibility and GPU/frame overhead at fixed quality. This is not physical sensor calibration.

**3. Shared instrument schema plus XR fit — R12/R13/R31/R32/R45.** Extract one selected-contact instrument specification containing label, state, evidence timestamp, enabled reason and explicit command reference; build DOM and XR adapters around existing dispatch. Pilot selection → inspection → explicit classification → response confirmation → receipt. Add reversible panel distance/scale/recenter controls with stored presentation preferences, and a selected-controller focus cue. Acceptance: equivalent accepted payloads/receipts in keyboard, simple pointer and emulator rays; no action on hover, no accidental second submission, no hidden disabled reason and no stale confirmation after contact/session change. Physical headset acceptance separately measures angular text/target size, missed hits, completion time, neck movement, comfort and sustained frame tails on named hardware; emulator success cannot close that gate.

All three experiments fit existing R01–R48 opportunities. **No R53–R56 entries are justified by this slice**: renaming synchronized evidence, scene fidelity or XR equivalence would double-count existing proposals. This report changes no shared source, registry, dependencies or release claims.
