# Training Ground: from setup dashboard to an observation station

Research/design brief, 24–25 October 2026. Selective source inspection resumed at `feature/vyuha-next-generation`, HEAD `147ff45`; concurrent implementation is not a frozen source or accepted release. This extends the [ultimate vision](VYUHA-ULTIMATE-VISION.md) and [UI/3D research](WORLD-CLASS-UI-3D-RESEARCH.md). It does not repeat NASA Eyes/Open MCT, Theatre or Academy research. No product source, dependencies, local browser, GPU workload or test suite was changed/run by this research workstream.

## Product decision

Make the Training Ground one **scene-led observation station** across entry, briefing, live decisions and completion. The world occupies the primary visual field. A stable instrument hierarchy explains its current meaning: presentation-only orientation, live modeled sensor imagery, paused/recovering state or a completed attempt. Mission configuration is a deliberate secondary task, not a wall of controls above the scene.

This is a Level 3 major upgrade when the complete ordinary training task is substantially reorganized and remains usable on keyboard, touch and fallback. Fullscreen styling alone is Level 2. A new active-inquiry simulation connected to authoring, debrief and progression may later reach Level 4; this slice changes neither acquisition semantics nor learning effectiveness. No claim of competitor superiority follows from the references below.

## What must actually change in VYUHA

`App.tsx` already owns the exercise phase, preparation, worker/session scope, accepted actions, pause/resume, restoration, completion and review. It also embeds setup, observation preferences, scene, radar, contacts, evidence and decisions in a long composition. `DecisionWorkspace.tsx` deliberately separates action content from evidence and is the mobile contact-selection focus target. `Scene.tsx` already uses observation-gated geometry/camera framing; `GuidedDecision.tsx` already controls explicit choices, guidance and feedback. The correct redesign preserves these meanings and replaces their spatial/phase organization.

The current live scene must not be described as lacking sensor gates, receipt handling, responsive controls or a decision workflow. The opportunity is **continuity and attention**: less configuration chrome before the user reaches the world, less scanning between disconnected instruments, and clearer transitions between looking, choosing, acceptance and outcome.

## End-to-end composition

| Phase | Primary experience | Invariants |
|---|---|---|
| Entry / no prepared attempt | An authored contact-free orientation world, concise training intent, visible recovery/assignment when applicable, and one primary Prepare action. Settings is secondary. | Orientation is labeled presentation-only. No contact routes, hidden labels, answer key, source event messages or advancing scored clock. Preserve assigned/recoverable entry paths. |
| Frozen briefing | The same stage carries a concise objective, environment, learning mode/assistance and frozen context, with one explicit Start action. Setup details remain inspectable. | A curriculum ticket is not regenerated as an ordinary adaptive drill. Preparing does not launch; arriving from Academy does not silently start. No future contact preview. |
| Live observation | A dominant sensor-origin image, compact status rail, radar/contact instrument and selected-contact decision dock. Preferences stay secondary. | No external overview/follow camera in live sensor mode. Sensor loss changes content and availability, not control location. Selected stale contacts remain visibly stale and cannot acquire invented current evidence. |
| Decision / acceptance | The user selects and inspects a contact, chooses an explicit action, submits through the existing path, then sees accepted/rejected/pending feedback in the same context. | Selection, hovering, changing channel or moving the camera never dispatches. Acceptance is not resolution; a seeded delayed response can remain pending or fail. No optimistic score/observation changes. |
| Paused / restoring | The same station explains whether local time is paused, instructor authority is required, or reconstruction is incomplete. | Settings overlays cannot secretly pause a server exercise. Restoration keeps actions unavailable until the canonical snapshot is ready. Do not replace the existing instructor-resume rule. |
| Completion | Freeze the attempt's identity and horizon, make verification/retry status clear, and offer the existing Theatre as the primary next investigation. | Local completion is not server verification. Retain unsynchronized evidence, export/retry and original record. A new attempt is explicit and receives its own context. |

Use one **active render context**, not independent 3D contexts for background, radar inset and modal preview. A persistent stage may preserve expensive assets, but camera, visibility cache and presentation state must reset at the correct boundaries. Entering live mode makes an immediate sensor-origin cut; any optional orientation animation is skippable, disabled for reduced motion and consumes no scored time. A failed context may be deliberately remounted or replaced by the existing tactical equivalent; persistence is a means, not an unconditional correctness requirement.

## Architecture the implementation can use now

**Presentation state.** A proposed `TrainingPresentation` derives phase, session/scenario identity, presentation kind (`orientation` or `sensor`), selected contact, foreground instrument, view/channel, modal state and focus-return target. It owns no accepted action log, score, canonical observation or worker clock. Keep App's existing authority until a separately tested controller extraction is justified.

**Scene policy.** Add an explicit contact-free orientation presentation adapter if necessary. It must remove contact geometry, labels, cues, inspection content and report-driven camera bounds—not merely make meshes transparent. Its external camera is permitted only before live observation. At Start, reset visibility/pose/selection caches using a phase/session context key, remove orientation framing, and consume only the existing live observation projection. A prettier sky or lighting rig must not change the modeled detection contract or fabricate silhouette detail.

**Semantic instrument contract.** Separate data/meaning from layout: selected report, age/availability, declaration, RF/IFF state, permitted action and disabled reason. Desktop, mobile and XR can arrange these differently, but they must share the original selectors and dispatch functions. A display swap retains contact, channel preferences where valid and pending action ownership. Avoid rebuilding the scene or replaying simulation on every hover, status message or modal state change.

**Stable action dock.** Recompose `DecisionWorkspace` around existing `GuidedDecision`; do not create a parallel command implementation. Keep explicit type/identity/response controls and their labels. Expanding evidence must not move a submit control under the user's pointer. When selection/session changes, stale drafts and confirmations follow existing invalidation rules. Fusion exposure receipts remain associated only with the accepted dispatch they belong to.

**Setup/preferences.** A deliberate settings/briefing modal is a genuine interaction redesign only if it preserves all required mode, seed, saved scenario, learner, assignment, quality, thermal, audio and guidance paths. Use existing modal-focus behavior, escape/close and focus return. Frozen curriculum fields remain locked. Quality, magnification and reduced motion are presentation preferences; instructional assistance remains a separate learning condition.

## Keyboard, mobile and accessibility patterns

Keep semantic DOM buttons/selects/inputs around the canvas. Provide direct links or controls to jump between **Observation → Reported contacts → Evidence and decisions → Exercise controls**. Contact selection should leave the user oriented; on small screens, offer a clear decision action rather than an unexplained forced context change. When explicit selection does move focus, announce the selected contact and place focus on a named region, preserving a route back.

The desktop can reserve a clear center for sensor pixels, with compact edge instruments and a dock outside that field. On mobile, show one major instrument at a time with explicit Sensor/Radar/Decision view controls and a persistent selected-contact/status summary. Do not shrink a desktop cockpit. A sheet containing decisions must be independently operable without mandatory dragging, swipe gestures, precision tapping or canvas selection; all reported contacts need a text-list alternative.

Use predictable Tab order matching visual order and retain focus across passive telemetry updates. Do not place every changing sensor value in an assertive live region. Announce meaningful phase changes, accepted/rejected decisions and loss/reacquisition; throttle or summarize recurring status. Keep input shortcuts scoped and optional so typing in settings and assistive-technology commands remain safe. If added, shortcuts select/open controls; they do not bypass confirmation or the accepted-action path.

Prefer opaque or strongly backed critical controls over live image pixels. Test their contrast against bright sky, thermal whites and night scenes. Preserve text plus shape/state distinctions for contact declaration, stale reports, sensor failure and pending action. Reduced motion removes arrival sweeps and unnecessary transitions; it does not remove relevant evidence. Fullscreen is optional, and a usable ordinary viewport remains available.

## Proportional acceptance for the first major slice

- **Entry and start:** ordinary demo, adaptive preparation, Academy ticket, saved scenario, assignment and recovery keep their correct source and explicit launch behavior. Orientation never advances scoring or reveals contacts. One primary phase-appropriate CTA is discoverable.
- **Live investigation:** keyboard and pointer can select a reported contact, switch the foreground instrument/channel, read availability and submit an explicit decision without losing context. The exact accepted payload/receipt and original assistance restrictions remain unchanged.
- **Boundary cases:** start while assets load, stale report/reacquisition, selected contact ending, sensor fault, resize, modal open/close, tactical fallback, context loss and restored session do not expose truth or enable invalid actions. Reference cameras never persist into live mode.
- **End and verification:** local completion, slow/rejected server verification, retry and offline cached review remain distinguishable. The completed attempt can enter Theatre without a new score or source record.
- **Actual interaction evidence:** real browser before/after tasks at desktop, tablet and narrow viewport, scale 1; keyboard focus/return, no horizontal overflow, usable primary actions, reduced motion and fallback. Static rendering/DOM tests support only the semantics they exercise; physical XR and screen-reader acceptance remain distinct.
- **Measurement:** count context changes/scrolls and errors in a fixed observe→inspect→decide→review task. Track scene mounts, interaction latency and frame tails only through existing opt-in diagnostics on matched device/workload. No speedup or learning claim without suitable measurements; no repeated whole-suite run merely for the layout.

The migration should replace the ordinary Training Ground composition while keeping the same original action/evidence contracts and a reversible implementation boundary. If the new station hides essential controls, leaks contact truth, destabilizes focus, alters assistance or loses recovery, restore the prior composition while fixing the replacement. Preserve new original art and presentation work; no destructive history/data migration is necessary for this slice.

The noticeable result should be an authored environment that takes the user from orientation into a coherent observation/decision task, not a larger hero image above the existing dashboard. Richer simulation, active evidence acquisition and empirically better teaching remain later connected transformations with their own model and validation gates.
