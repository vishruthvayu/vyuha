# Startup follow-up: occupied localhost listener

After renderer milestone `be77b5bb2b3e661602fb12e47c7ca5955ec6d563`, actual clean-clone acceptance reproduced a preflight defect on macOS: an existing `127.0.0.1` listener did not make the reusable `0.0.0.0` probe fail. This happened with and without reuse on the existing listener. A wildcard-only probe can therefore report success while localhost reaches another service. The earlier successful wildcard-listener regression did not cover this case.

The original failing regression is preserved in `work/finale/ultimate-experience/engine-closure-20261015/loopback-listener-before.log`: **2 failed /2 passed**. `scripts/preflight.py` now explicitly probes both `127.0.0.1` and `0.0.0.0`, using POSIX `SO_REUSEADDR` for restart compatibility and Windows `SO_EXCLUSIVEADDRUSE` when available, never `SO_REUSEPORT`. Each probe also calls listen. This covers wildcard/localhost occupied listeners without changing simulation, security credentials or scoring. It does not claim an exhaustive inventory of every specifically bound interface or native Windows/Linux execution.

`server/tests/test_rc2_startup.py` now checks occupied wildcard and loopback listeners with reuse off/on, and five immediate restart cycles after active HTTP connections for each host.
