# Review and analytics workflows — Ultimate experience

## Source inspection and completed implementation

The original AAR showed four detached score metrics and raw JSON decision details. Analytics expanded every detail at once and left two wide tables without bounded scroll wrappers. What-if and Fusion review had genuine late-response ownership defects; Analytics ignored late successes but not all late errors. Six mounted tests reproduce these defects against original source before corrections.

The new markup follows the shared **Precision Command** contract: calm graphite/navy surfaces, ice-cyan accent and restrained semantic status colors. Root owns all CSS centrally; this workstream introduces semantic hooks only.

- **Decision path:** four native button stages in an ordered list, showing exact final-contact-node scores and authoritative review counts. Select a stage, inspect readable recorded/reference/evidence/consequence branches, and invoke `onReview(DecisionReview)` to open the exact original replay boundary. A complete ordered text alternative remains available. Rubric stage order is explicitly distinguished from actual decision timing and causality. Legacy 15-point timing remains labelled correctly.
- **Analytics:** default persisted overview, native pressed view controls, then scenario × skill, session comparison, Director history or unit trend. Scope changes clear previous evidence and reject late failures. The initial trainee is obtained from the roster instead of an invented CADET-01 request.
- **Trends:** original SVG plots actual persisted Beta means in processed sequence. Colors have distinct line patterns; labelled checkboxes isolate series. The full exact-value table retains the prior and every ledger entry. A bounded latest-80 plot never incorrectly joins truncated history to the original prior.
- **Ghost:** native previous/next finding controls retain exact replay callbacks. A real H2 fixes heading structure, verification state is explicit and empty timeline filters have readable feedback.
- **Reference/What-if:** separate original and hypothetical score cards, with immutable-history and evidence/canonical scope boundaries retained. Request generations prevent a late branch from appearing in another session. Reference session/mode ownership guards are preserved; foreign-session policy responses are rejected.
- **Fusion:** reconstructed receipt count, optional confidence sample count and actual mean Brier are presented separately; missing diagnostics show `Not logged`. Client-reported association never becomes a human viewing, causal reliance or learning-efficacy claim. Load/sync ownership guards and retry feedback support recovery.

## Evidence rules

Scores and persisted observations are unchanged. No readiness percentage, learning-effect metric, certified-expert claim, optimal-result claim or real-world effectiveness claim is introduced. Final contact-node scores are shared across attempts; they are never added into per-action awards. After-review truth remains explicitly separated from decision-boundary observations. Shared Crew training does not contribute to individual learning profiles.

## Supporting accessibility research

[W3C WAI complex-image guidance](https://www.w3.org/WAI/tutorials/images/complex/) supports a concise diagram description with a full structured textual alternative. The path uses ordinary ordered-list content and buttons instead of a canvas-only tree; chart values are retained in a complete table.

[WAI APG tabs guidance](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) specifies keyboard behavior for true ARIA tabs. This implementation uses native pressed buttons for view selection, retaining ordinary Tab/Enter/Space without incomplete custom tab semantics.
