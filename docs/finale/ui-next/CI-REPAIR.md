User reported repeated **Check training build / verify** failure emails. Inspected the actual [5701574 run](https://github.com/vishruthvayu/vyuha-sih26247/actions/runs/38937345953) and an [earlier 59aae16 run](https://github.com/vishruthvayu/vyuha-sih26247/actions/runs/38927134745). Both failed the same three restart/preflight cases in `server/tests/test_rc2_startup.py`, reporting `Frontend assets missing`. Latest failed run: 705 passed, 3 failed. Frontend and Docker steps were skipped because backend tests stopped the job.

The workflow ran pytest before npm installation/build. Those integration tests invoke real production preflight, which correctly requires `client/dist/index.html`. Local checks already had built assets, hiding the clean-runner ordering defect. The workflow now installs and builds frontend production/offline assets **before** backend tests. No preflight check or regression assertion is removed. Added named lint and formatting steps so hosted verification includes checks already required locally. No application, drill-owned file, dependency, authorization or scoring change.

Reproduced against a fresh detached checkout of `5701574` with no dist: **3 failed, 10 passed** in the startup suite. After `npm ci` and `npm run build`, the same suite passes **13/13**. Full frontend **301/301**, including Python parity, lint, formatting, production build and Docker image build pass in that checkout. Local parity reuses the prepared pinned Python interpreter; GitHub retains its fresh Python 3.12 environment and all backend/frontend/Docker checks. Logs are in [ci-repair/](ci-repair/startup-after-build.txt).

The authoritative hosted result belongs to the new commit's **Check training build** run. Historical failed commits remain failed; rerunning unchanged old source would repeat the defect. Notifications were not disabled, tests were not skipped, and no unrelated branch was changed. Main Codex should preserve this workflow ordering when merging the hardening branch.
