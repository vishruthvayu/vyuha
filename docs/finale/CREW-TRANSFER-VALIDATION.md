# Shared Crew and Fusion transfer

Completed Crew Mode records carry a strict optional `shared_crew` snapshot. It contains a pseudonymous crew identifier, a generic label, pseudonymous member identifiers and roles, and complete action-order attribution. It contains no original crew label, member callsigns, role codes, role-code hashes, clock cache or live permissions. Every action must have exactly one attribution matching its frozen spotter/responder role.

A shared result uses `outcomes: null` and has no individual profile snapshot for its synthetic owner. Export does not invoke lazy individual-profile backfill for crew owners. Import reconstructs the ordinary authoritative score and Ghost review, then stores an immutable crew archive with accepted events and commands. It creates no individual Beta rows or outcome ledger. Importing an archive does not create a live crew or usable member code. Archive access requires officer authentication; runtime input endpoints are blocked.

Fusion transfer carries only strictly typed exposure requests, including optional confidence distributions and client-reported association. Stored advice/receipts are not trusted or exported. Import reconstructs the accepted log at each exact exposure boundary using one batch replay, validates identifiers and associations, and regenerates receipts before any database writes. Duplicate imports compare the complete exposure set, request bodies and regenerated receipts. The receipt’s association remains a client self-report; it does not establish human viewing, causal reliance, calibrated confidence or training efficacy.

Focused tests use real API routes, server role capabilities, temporary SQLite databases and ordinary JavaScript JSON conversion. The deterministic clock is controlled in software to exercise accepted role actions. This is software validation on macOS, not new physical multi-device or Windows/Linux validation. The tests cover source/clean-recipient/forwarding behavior, exact score/AAR/receipt preservation, zero shared Beta credit, individual Fusion profile preservation, rejected signed metadata changes and atomic rollback. See `CREW-TRANSFER-RECEIPT.json` for the final result and scope.
